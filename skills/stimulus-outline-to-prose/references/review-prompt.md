# 审稿

## 审稿要求（发给每位审稿人的原文）

5 位审稿人拿到的是同一份原文。只替换一处：【正文】放全篇正文，按原样分段。不带“单元”标题，也不带篇名。

```
你是一位独立审稿人。

【先说清楚】
- 你的上下文里可能有关于某位用户的资料、偏好、记忆、技能列表或其他对话内容。全部忽略，不要参考。
- 不要调用任何工具。
- 只根据下面给出的正文来审。
- 直接给出完整的审稿报告，不要提问，不要等确认。用中文写。

【这篇稿子会怎么发】
一篇纯文字帖，发在 TikTok、X、Instagram 这类快节奏平台上。读者刷到、看到的，就是下面这段文字。

【正文】（以下是全文，按原样分段）
<<<
（全篇正文）
>>>

【审稿要求】
下面 6 项，每项都要审，每项打一个 10 分制的分数（可以带一位小数）。
打分参照：10 = 顶尖，几乎挑不出毛病；8 = 好，只有小问题；6 = 及格，问题明显；4 = 差；2 = 很差。

1. 句句刺激：逐句看，找出读着平的句子和空转的句子；刺激够不够强、新不新，老梗算弱刺激。
2. 人设：人物站不站得住，前后有没有走样；讨不讨喜、有没有记忆点。只看读者读下来的感受。
3. 语言口吻：口吻统不统一，有没有语病、啰嗦、AI 味。
4. 衔接：句与句、段与段、节拍之间、场景之间接不接得上。
5. 故事整体：每个点是不是一个比一个大；结尾收不收得住、有没有余味；埋的线有没有收回来；有没有逻辑硬伤或让人出戏的地方。
6. 快节奏平台：模拟这篇文字发在 TikTok、X、Instagram 这类快节奏平台上——刷到时停不停得下来，读到哪儿会划走，会不会点赞、评论、转发，读完想不想关注、追下一篇，能不能成爆款。

只指出问题，不要给改法。每条问题要指到原句（原样引用，可以只截关键的一段），再用一两句话说清问题在哪。条目清晰，语句简洁。
```

## 审稿报告文档《篇名 · 审稿报告》

篇名还没定的话，先用暂定名，定了再改。页面按这个顺序：

1. **最终报告**：AI 写，结构见下一节。
2. **审稿人A（模型）到审稿人E（模型）**：每人一页，报告回来就原样贴进去。换了模型的，页名跟着改。没审完的，在那一页写明原因。
3. **审稿要求**：发给审稿人的原文，放在代码块里，并写明各位审稿人用的模型。

## 最终报告的结构

- **开头**：用一两句话说结论，比如平均分、能不能成爆款、最大的问题在哪。写明用了哪几份报告，谁换了模型，谁没审完。
- **分数**：一张表，列出每人的各项分数、每项的平均分、每人的平均分。分数用代码算，不要心算。
- **问题清单**：
  - 一张表，列是 #、问题、涉及原句、几人提到、我的判断。
  - 重复的问题合并，按几人提到、问题多严重排序。
  - “我的判断”先打标签：【要改】【可改】【预期内】【存疑】，再用一句话说为什么。
- **快节奏平台**：一张表，三个平台各占一行，写停不停得下来、在哪儿划走、互动和关注。再加一句爆款判断，以及最可能出现的评论。
- **分歧**：审稿人意见差别大的地方，写清我站哪边、为什么。
