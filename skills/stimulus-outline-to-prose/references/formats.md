# 格式

下面的样子都来自第一次试跑，篇名是《秘密是装在肚子里的》。

## 这一篇的文档（四页）

### 细纲页

- 一级标题“细纲”，下面一行是日期和作者。
- 用户给的细纲原样放进来。
- 用户标出单元后，在这一单元的细纲上方加二级标题“单元X”。
- 不加“当前单元”之类的说明行。

### 候选池页

- 一级标题“候选池”，下面是二级标题“单元X”。
- 可以先放一句说明，比如：“要哪条就勾上；可以直接在这里改，挪进已确定池的是你改过的版本。补你自己想法的那几条，先列了你的原话。”
- 然后放 10 条候选，每条的样子：

````
- [ ] **1**

林子里有一半的树，是小松鼠忘出来的。

它记性不好，每年秋天藏下的松果……第二年春天都长成了小松树。

（搞笑+妙：噗，忘出了一片林子）

- [ ] **3 · 补你的第1条**

你的原话：

```
1-行为与语言反差
“猫猫，我可以相信你吗？”
“当然可以！”猫猫（与“值得被相信”形成反差的动作行为），用力挺起了胸膛。
```

“猫猫，我可以相信你吗？”

“当然可以！”猫猫正从一个树洞里往外钻，钻到一半，卡住了……

（反差+搞笑：噗，你先出来再说）
````

- **勾选框**只放在编号那一行。勾上后，这一行会变灰、加删除线，这是文档本身的样子；实写不受影响。不用下拉标签，用户试过，不要。
- **用户原话**放进代码块，不用引用格式，方便复制。原话照抄，包括用户自己写的编号和小标题。
- **只替换用户原话里的某一句**时，原话只列那一句，编号行写明“可换掉‘……’那句”。
- **实写**用纯文本段落，不用引用格式。对白各自成段。
- **最后一行**是刺激类型和读者反应，跟细纲的格式一样。跟后文有呼应的，可以顺手点一句，比如“点1接得上”。

### 已确定池页

- 一级标题“已确定池”，下面是二级标题“单元X”。
- 勾上的候选原封不动地搬过来：勾选框（仍是勾上的）、编号行标签、原话代码块、实写、刺激类型行，都照旧。
- 只把序号按顺序重排成 1、2、3……

### 正文页

- 一级标题“正文”。
- 篇名定了以后，在一级标题下面加一行加粗的篇名，位置在第一个“单元”标题上方。
- 二级标题“单元X”下面是正文段落，纯文本。

### 标签.md

- 一级标题“分类标签”，下面是说明。
- 总表的每一行写成 `| [标签](#标签) | 条数 |`，按条数从多到少排。
- 总表下面是 `---`，然后每个标签一节，用二级标题，列出它下面的所有记录。每条写成 `- [刺激点短名](记录/文件.md#跳转名)：实写正文`。

### 跳转名

按 GitHub 的规则写：去掉标点，空格换成 `-`。比如“发三次誓 加码”写成 `#发三次誓-加码`。同一篇里短名重名的，从第二条起，末尾依次加 `-1`、`-2`。

### 推送和核对

1. 先读 README，再把整个仓库捋一遍，所有跟着变的地方一起更新：
   - 新增这一篇的记录文件；
   - 标签.md：总表的条数和顺序，各节下的记录；
   - README 等说明里，凡是跟这次改动有关的地方。
2. 直接提交到 main，提交信息写清这次入了哪一篇。
3. 推完核对链接：
   - 用 `gh api repos/1d-a/stimulus-bank/contents/<URL 编码的路径> -H "Accept: application/vnd.github.html"` 取渲染后的页面；
   - 提取里面的 `id="user-content-…"`，和标签.md、记录文件里的每个跳转逐个对；
   - 通用的 `/markdown` 渲染接口在这里用不了；
   - 有断的，修好再推。
